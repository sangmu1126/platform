# 실제 온프렘 시험 관측 연결

기존 Sova 셸·메뉴·워크로드 움직임을 유지하고, 별도 운영자 시험 도구의 실제
API·HTTP 관측을 같은 `console-workload.v1` 조회 계약으로 연결한다.

## 구성

```text
운영자의 명시적 전용 시험 실행
  → 기존 보안 대응 계약·효과 원장·Kubernetes 어댑터
  → 전용 원본·대체·독립 확인 namespace
  → API UID + 새 HTTP 연결 + 실제 응답 nonce
  → 개인 파일의 HMAC 결속 관측
  → 조회 전용 PlanWorkload → 기존 Sova 워크로드 지도
```

`testing/onprem_response_console.py`는 소스 체크아웃 전용 도구다. 제품 wheel이나
운영 호스트에 설치하지 않는다. Kubernetes·AWS 자격을 받지 않고 변경 API도
제공하지 않는다. 실제 변경은 등록된 개인 접속 도구 안의 별도 CLI만 수행한다.

## 신뢰 경계

- 생산자 ID·40자리 소스 SHA·실제 계획·관측 본문을 HMAC으로 묶는다.
- 소유자 전용 일반 파일만 읽고 symlink·공개 파일·변조·다른 계획을 거부한다.
- 기존 `PlanWorkload`의 권한 검사와 조회 전후 계획 결속을 재사용한다.
- SHA나 본문 해시만 맞는다고 생산자를 신뢰하지 않는다.
- 루프백 Host·일회용 접속 주소·HttpOnly 쿠키·2시간 제한을 사용한다.
- GET·HEAD만 허용한다. 브라우저에서 클러스터 변경·계획 승인·전환을 요청할 수 없다.
- 개인 시험의 실제 자원 참조를 로컬 PlanStore에 등록하되 상태는 `COLLECT`다.
  T10 제품 승인·T19 PASS·S2 완료를 만들지 않는다.
- 관측 시작 시각부터 유효 시간을 계산한다. 수집 지연이나 종료로 만료된 근거를
  다시 현재 시각으로 발행하지 않는다. 종료 자료는 현재 격리·복구 주장에 사용하지 않는다.

## 화면 의미

- 원본·대체 API, 독립 HTTP 서비스, 고정 시험 진입점, 독립 확인 Pod를 표시한다.
- 원본 API의 선정한 설정 위반과 실제 확인 경로의 접속 거부를 구분한다.
- 격리 영역 이동은 상태를 표현하는 화면 배치다. 물리적 Pod 이동을 뜻하지 않는다.
- 대체 기동은 실제 별도 Deployment의 0→1 변경이다.
- 경로 전환은 전용 HTTP 진입점의 실제 응답 대상 변경이다. 운영 Edge나 DB 컷오버가 아니다.
- 일반 공격 탐지·전체 네트워크 봉쇄·운영 앱 복구로 확대하지 않는다.
- 기존 로컬 시나리오는 합성으로 계속 구분한다.

## 검증

조회 전용 호스트 시험 8개와 기존 workload 조회 시험 34개, 총 42개가 통과했다.
변조·다른 소스·잘못된 서명·키 교체·다른 계획·공개 파일·symlink·외부 Origin·변경 요청을
거부하고, 만료 시각을 갱신하지 않는지 확인했다. 이는 로컬 계약 시험이다.
실환경 결과·자원 정리·브라우저 수신 기록은 별도 비공개 실행 근거로 관리한다.
