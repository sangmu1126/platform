## 구현 범위

`PlanStore`에 새 합성 계획을 등록하고 `CollectionProof`와 `WorkflowRecovery`로 다음 경로를 진행한다. SQL로 상태를 지정하거나 운영 계획의 실패를 지우는 경로는 없다.

```text
COLLECT → ANALYZE → PROPOSE → REHEARSE → GATE
→ AWAIT_APPROVAL → SHIFT → CUTOVER → WATCH → DONE
```

사람의 변경 승인·SHIFT 승인·컷오버 승인은 각각 기존 T10 서비스에 저장한다. 합성 실행자는 별도 로컬 주체이며, T10이 실행 명령을 접수한 뒤에만 데모 DB에 효과를 한 번 기록한다. 재시작해도 같은 계획·승인·효과를 읽는다.

합성 시험은 기존 T19 `evaluate`/`consume`에 전달한다. 게이트 BLOCK을 PASS로 바꾸지 않는다. 실행 직전에 다시 평가하며, 승인 후 입력이 달라지면 실행되지 않는다. 게이트 프로필은 `demo-gate`의 3개 시험이다. 전체 20개 시험의 운영 PASS가 아니다.

상단 데모 패널만 별도 모듈로 주입해 기존 Sova UI와 서버 계약을 보존한다. 나머지 콘솔도 같은 T10 계획·이벤트를 조회하며, 브라우저 검증에서 새로고침 후 기존 콘솔의 완료 표시와 SSE 연결까지 확인했다. 원래 UI 인계 브랜치에는 데모 패널을 추가하지 않았다.

## 검증 결과

데모 회귀 시험은 사람 승인 누락, 다른 계획 증거, 대상 실패, 필수 시험 누락, 승인 이후 증거 변경, 응답 유실, 재시작, 중복 클릭, 유효기간 만료, 운영 DB/심볼릭 링크 디렉터리 거부, 미인증·다른 Origin/Host·중복 JSON 키·과대 요청 거부를 포함한다. 정상 경로 시험에서는 외부 소켓 연결과 하위 프로세스 실행을 금지한 상태로 DONE을 확인했다.

최초 브라우저 실행은 설정 파일 기준 작업 디렉터리 때문에 서버를 찾지 못했다. 테스트 서버의 작업 디렉터리를 명시한 후 통과했다. 통과 수치에 첫 실행을 포함하지 않는다.

원시 접속 파일·브라우저 증빙·wheel 해시·검사 결과는 로컬 비공개 검증 폴더에 보존한다. 일회용 URL·쿠키·원래 운영 요청 식별자는 공개 문서에 포함하지 않는다.
