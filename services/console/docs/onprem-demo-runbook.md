# Sova 워크로드 지도·보안 대응 시연

기존 Sova UI에서 실제 온프렘 전용 시험을 준비하고 대응·정리한다.
설치 wheel과 플랫폼 운영 API에 넣는 기능이 아니라 개인 운영자용 시연 도구다.

## 시연 순서

1. 개인 실행 도구로 콘솔을 열고 **워크로드 지도**를 선택한다.
2. 변경 범위를 읽고 체크한 뒤 **실제 시험 준비**를 누른다.
   새 namespace 세 개를 만들고 실제 응답을 수집한다. 정상 연결을 지도에서 확인한다.
3. 다시 범위를 체크하고 **설정 위반 주입·대응 실행**을 누른다.
   원본 API의 읽기 전용 root 설정을 해제하는 통제된 위반을 주입한다.
4. 원본 API의 경고, 격리 영역으로의 화면 이동, 차단 연결을 확인한다.
   격리 대상이 아닌 이웃 HTTP 서비스는 계속 응답해야 한다.
5. 대체 API 기동·HTTP 확인·고정 시험 주소의 Green 전환을 확인한다.
   하단 네 단계는 효과 원장에서 실제 확인된 결과가 있을 때만 완료된다.
6. **시험 종료·자원 정리**를 누른다. UID를 대조해 삭제한 뒤에만 다시 준비할 수 있다.

격리 영역 이동은 논리적 상태 표시이며 실제 Pod 이동이 아니다. 전환 대상은 전용
시험 HTTP 주소다. 운영 채팅 앱, DB, 플랫폼 호스트, 기존 namespace는 변경하지 않는다.

## 실행 전 조건

- 개인 Tailscale 접속과 등록된 온프렘 RKE2가 사용 가능해야 한다.
- 개인 접속 도구·프로필의 고정 해시와 클러스터 UID가 일치해야 한다.
- 설정에 등록한 Sova/security 소스가 고정 SHA와 일치하고 변경되지 않아야 한다.
- 현재 실제 노드의 아키텍처를 지원하는 지정 digest와 Python 실행 환경을 사용한다.
- 클러스터 연결 실패를 정상 상태나 합성 시연으로 대체하지 않는다.

개인 실행 파일은 비공개 로컬 도구 폴더에 둔다. 실행 파일 하나로 서버와 일회용
접속 주소를 열 수 있으며 키·토큰을 입력하거나 복사하지 않는다. 이미 같은 서버가
실행 중이면 중복 실행하지 않는다. 콘솔은 루프백으로만 열리고 2시간 후 종료한다.

## 시간과 실패 처리

- 각 시험은 개인 자격보다 짧은 최대 8분 안에서 동작하고 자동 정리한다.
- 준비 후 남은 시간이 4분 미만이면 대응 실행을 막는다. 종료 후 다시 준비한다.
- 대응 계획은 새로 수집한 근거와 결속하고 최대 5분·시험 종료 기한 이내로 제한한다.
  이미 실행 중인 승인을 자동 연장하지 않는다.
- 응답은 실제 클러스터 확인을 기다리므로 각 단계에 시간이 걸린다.
- 근거가 만료되면 현재 상태 주장을 철회한다. 진행 상태와 과거 영수증은 구분한다.
- 중복 요청은 같은 실행으로 처리하고, 응답 유실 시 자동 재전송하지 않는다.
- 정리 결과가 불명확하면 새 시험을 막는다. 기존 UID와 실행 원장을 먼저 조회한다.
- 브라우저를 닫아도 워커의 기한·정리 처리는 유지된다. 서버 종료가 운영 자원의
  무조건적 삭제나 복구 완료를 보장하는 것은 아니다.

## 승인·보안 경계

브라우저는 고정된 `prepare / respond / stop`만 요청한다. 이미지·namespace·명령·URL은
입력받지 않는다. 개인 세션, 정확한 Origin, CSRF, 현재 시험·계획 결속을 검사한다.
응답 실행 요청은 별도 도메인의 HMAC으로 서명하고 소스 SHA·계획·요청 ID·만료를
워커에서 확인한다. 기존 효과 Guard·원장·UID 검사도 유지한다.

콘솔의 `/v1` 변경 경로는 계속 닫혀 있다. 이 승인은 개인 전용 시험의 승인이다.
T10 제품 승인, T19 통과, 일반 공격 탐지나 운영 무중단 이전의 완료로 사용하지 않는다.
개인에게 부여된 클러스터 권한 자체가 최소 권한으로 축소됐다는 의미도 아니다.

## 실행 기록

각 실행의 개인 상태 폴더에 소스 기준, 자원 UID, 효과 영수증, 관측 서명, 정리 결과와
비공개 로그가 남는다. 공개 문서·PR에 실제 접속 자료나 쿠키·서명 키를 복사하지 않는다.
실제 UI 인수 결과는 별도 개발 기록에 연결한다.
